# Bodytype boundary sensitivity v2

A deterministic sensitivity analysis of Bodytype's v2 four-girth body type
classification rules on a synthetic rule-space grid of **669,858 tested
points**.

This repository contains the analysis code, method, schema, public aggregate
tables and three accessible SVG figures. The full 669,858-row parquet grid is
prepared for the dataset release and is not stored in this repository.

- Source page:
  https://bodytype.org/research/boundary-sensitivity-body-type-calculator
- Algorithm version: v2
- Dataset version: 1.0.0
- Site status: the source page is currently `noindex` while author attribution
  and methods review are pending.

## What this is not

- Not a population sample or a body-shape survey.
- Not an accuracy, sensitivity, specificity or confidence study.
- Not a measurement-error distribution. The ±0.5, ±1 and ±2 cm shifts are
  sensitivity parameters.
- Not medical data or a medical device.
- No user measurements or personal data are included.

## What was scanned

- 669,858 synthetic rule-space points.
- Seven hip sizes: 80 to 140 cm.
- Bust-to-hip ratio 0.900–1.100, waist-to-hip 0.650–0.950 and
  high-hip-to-hip 0.700–1.000, each at 0.005 steps.
- Ordering constraint: waist < high hip < hips.
- Single-field shifts of ±0.5 cm, ±1 cm and ±2 cm; only one field changes at
  a time.
- Rounding paths: 0.5 cm, 1 cm and 0.1 inch, plus an exact cm → in → cm
  round-trip check.

## Key results

- **158,352 of 669,858 tested points (23.6%)** changed label under at least
  one single-field ±1 cm shift. The ±0.5 cm and ±2 cm results are 76,113
  (11.4%) and 307,610 (45.9%).
- **154,674 points (23.1%)** had a stability radius below 1 cm;
  **421,650 (63.0%)** were below 3 cm. **43,715 points (6.5%)** sat exactly on
  a threshold.
- The most frequently crossed threshold was `bustToHip:1.05`
  (123,702 of 324,100 ±1 cm flip events, 38.2%), followed by
  `bustToHip:0.95` (119,034; 36.7%).
- Rounding to 1 cm changed 20,095 labels (3.0%); rounding to 0.1 inch changed
  25,820 (3.9%); rounding to 0.5 cm changed 1,449 (0.2%).
- The exact cm → in → cm check changed 3,417 labels, all at boundary points.
  This comes from floating-point representation near equality; Bodytype v2
  does not apply a tolerance, and the result is recorded rather than hidden.

These are properties of a deterministic rule set on a synthetic grid, not
population shares, probabilities or accuracy estimates. No confidence
intervals are reported because the scan is deterministic, not a random sample.

## Reproduce

```bash
pnpm install
pnpm analysis:boundary
```

The script uses Vite's SSR module loader to import the TypeScript rule modules
directly; it does not copy the classification logic. It writes the full CSV to
`data/boundary-sensitivity/v2/<run-date>/` and the public snapshot to
`public/data/research/boundary-sensitivity/v2/`.

Convert the full CSV to parquet and verify it:

```bash
pnpm analysis:parquet
pnpm analysis:verify-parquet
```

The converter currently reads the recorded `2026-11-16` run directory. If you
rerun the scan on another date, update the run date in
`scripts/analysis/csv-to-parquet.mjs` first.

Different commits or Node versions may produce different outputs. Record the
commit, Node version and checksums with any redistribution.
