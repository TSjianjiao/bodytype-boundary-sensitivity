## 1. Rule source

The scan calls the project implementation directly:

- `lib/body-type/ratios.ts`: `classifyId`, `computeRatios`
- `lib/body-type/stability.ts`: `findNearestShift`
- `lib/body-type/algorithm.ts`: `measurementWarnings`
- `lib/body-type/thresholds.ts`, `lib/body-type/types.ts`,
  `lib/body-type/units.ts`: constants and type order

The scan does not copy the classification logic and does not define a second
set of thresholds.

Bodytype v2 thresholds:

- `BUST_BALANCE = 0.05` (bust-to-hip ratio 0.95 to 1.05 is balanced)
- `WAIST_DEFINED = 0.80`
- `WAIST_UNDEFINED = 0.88`
- `HIGH_HIP_CURVE = 0.95`

Label order: Inverted triangle → Pear → Apple → Hourglass → Rectangle.

## 2. Grid parameters

- Hip circumference: 80, 90, 100, 110, 120, 130, 140 cm (7 levels).
- Bust-to-hip ratio: 0.900 to 1.100, step 0.005 (41 levels).
- Waist-to-hip ratio: 0.650 to 0.950, step 0.005 (61 levels).
- High-hip-to-hip ratio: 0.700 to 1.000, step 0.005 (61 levels).
- Ordering constraint: waist ratio < high-hip ratio < 1, i.e.
  waist < high hip < hips.
- Expected tested points: 669,858; observed rows: 669,858.
- Ratios are generated from integer thousandths to avoid floating-point step
  drift; centimetre values are not pre-rounded.
- Supplementary warning set: points with high hip ≥ hips or high hip ≤ waist.
  They are written to `warning-cases.csv` and are not part of the main
  denominator.

The grid is a reproducible rule-space construction. It is not a model of the
distribution of real bodies.

## 3. Perturbations and rounding

- Single-field shifts: bust, waist, high hip and hips are each shifted by
  ±0.5, ±1 and ±2 cm. Only one field changes at a time.
- A shifted point outside 40–200 cm is skipped for that comparison and
  recorded in `skipped_out_of_range`.
- A flip means the shifted `classifyId` differs from the base label.
- Rounding paths: 0.5 cm and 1 cm round half up; 0.1 in first converts with
  1 in = 2.54 cm, rounds to 0.1 in, then converts back to centimetres.
- Unit consistency check: exact cm → in → cm conversion, with no intermediate
  rounding.

## 4. Stability radius and denominators

- `findNearestShift` uses a monotone binary search and quantises the radius to
  0.01 cm. A radius of 0 means the input itself sits on a boundary; Infinity
  means no other label is reachable within the 60 cm search limit.
- Every rate uses the number of tested points that participate in that
  metric, not a number of people.
- The transition matrix counts ±1 cm single-field, single-direction flip
  events. Multiple events from one point to the same target label are counted
  separately.

## 7. Reproduction

```bash
pnpm install
pnpm analysis:boundary
```

The script reads the rule modules through Vite SSR and writes the full CSV to
`data/boundary-sensitivity/v2/<run-date>/` and the public snapshot to
`public/data/research/boundary-sensitivity/v2/`. The full CSV is kept out of
the site repository.

To rebuild the parquet file from the full CSV:

```bash
pnpm analysis:parquet
```

Different commits or Node versions may produce different output files. Record
the commit, Node version and checksums with any redistribution.

## 8. Known boundary decisions

- The 3,417 exact cm → in → cm label changes all sit on boundary points. They
  come from floating-point representation near equality; v2 does not apply a
  tolerance. This is recorded, not hidden.
- The 36 supplementary points with high hip = hips do not trigger the current
  warning. The wording and implementation difference still needs a decision
  before the analysis is treated as final.
- No confidence intervals are reported. The scan is deterministic, not a
  random sample.
